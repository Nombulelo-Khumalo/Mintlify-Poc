# Biostore Containerization 

## Overview

This guide provides a reference for the complete workflow for packaging the **Alcazar Biostore** application as a Docker image
and deploying it to a Kubernetes environment.

For simplicity, this guide uses `MicroK8s` as the Kubernetes platform.
This deployment is suitable for development, testing, or very small production environments.

For larger or enterprise production deployments, a more robust and targeted deployment architecture should be considered.

---

## Linux Distribution

**Alcazar Biostore** has been deployed and tested on the following distros:
* Ubuntu 22.04

It is expected that it will work equally on these distros, although minor changes might be required to this deployment process
* Debian 12
* Red Hat Enterprise Linux 9
* CentOS 9

## Important Notes

The **Alcazar Biostore** service is a REST API application, and its containerization process follows the standard approach described in the @linux-containerization guide.

Since this containerization guide is valid for all Alcazar REST API services, it uses generic placeholders for application-specific values. 

Following these recommendations ensures consistent containerization. The required or recommended actual replacement values for **Alcazar Biostore** are listed below.

* Be mindful of case sensitivity, uppercase and lowercase characters must match precisely e.g `Biostore` and `biostore` are different on a Linux system.
* The `<App File Name>` may differ according to deployment package
* The `<Internal Port>` should match the application's `appsettings.json` or Kestrel Port.


| **Placeholder**         | **Recommended Value**                                   |
| ----------------------- | --------------------------------------------------------|
| `<App>`                 | Biostore                                                |
| `<App Name>`            | biostore-service                                        |
| `<NLog File Name>`      | NLog-linux.config                                       |
| `<App File Name>`       | Alcazar.Biostore.Core.dll                               |
| `<Internal Port>`       | 5001                                                    |
| `<Pod Name>`            | biostore-service                                        |
| `<DNS Name>`            | Local domain, FQDN or IP Address                        |
| `<Remote Testing Link>` | https://`<Domain Name>`/`<Virtual Folder>`/swagger/index.html   |
| `<Domain Name>`         | Local domain, FQDN or IP Address e.g `api.company.com`  |
| `<IP Address>`          | The address of the hosting server e.g `123.456.789.012` |
| `<Virtual Folder>`      | biostore-service                                        | 
| `<Conf Path>`           | /usr/share/Alcazar/<App>/conf                           |
| `<Log Path>`            | /usr/share/Alcazar/<App>/logs-service                   |


The `<NodeIP>` and `<NodePort>` values are automatically assigned by `MicroK8s` or the Kubernetes platform being used.

To retrieve these values, run the following commands:

**NodeIP**

The value of the INTERNAL-IP represents the `<NodeIP>`

```bash
microk8s kubectl get nodes -o wide
```

**NodePort**

Under ports, you will have `<Internal Port>:<NodePort>/tcp`

```bash
microk8s kubectl get svc
```
