# Alcazar Biostore Deployment Guide (Linux)

## Overview

This document provides a deployment reference for **Alcazar Biostore** on Linux.
It is intended for system administrators and developers who are setting up the application on a Linux server.

At this stage, this guide only covers the deployment of the Biostore service, the Biostore agent and website will be added at a later stage.

This guide describes a simple deployment, where the application and database are hosted on the same server. 
This deployment is suitable for development, testing, or very small production environments.
For production deployments, a more targeted deployment architecture need to be considered.
You might separate the database onto its own server, or use a serverless database service from a cloud provider.
You might implement additional security measures, such as firewall rules. This guide does not cover these advanced deployment scenarios.

## Additional Notes

### Native Libraries
This application requires native libraries for some of its adapters.
Please ensure that Linux-compatible .so (shared object) libraries are copied to the appropriate system directory.

```bash
sudo cp libbio_key-6.6.so /usr/local/lib/
sudo cp libbiocred.so /usr/local/lib/
sudo ldconfig
```

### Background Tasks Configuration

Please note that as of this release, background task variables have moved from `startup.config` to `background.config`. The background config set is stored in the database by default, but can be configured to reside in a file. Variables are migrated automatically, but it is advised to verify that variables have been migrated successfully; and then delete the `<Tasks>` section from `startup.config`.

Where multiple applications share the same database, it is required to configure the path of `background.config` differently per application. This is illustrated later in this document.

### Web.config Configuration

Biostore uses Newtonsoft for JSON serialization, so Swagger must also be configured to use Newtonsoft.
If Swagger uses a different serializer, request and response payloads may not serialize correctly.

By default, `UseNewtonsoft` is set to `false`. To enable Newtonsoft support, add the following configuration under `SwaggerOptions` in your `web.config` file:

```xml
<SwaggerOptions>
    <ShowSwaggerUI value="true" />
    <UsePathBaseForSwaggerEndpoint value="true" />
    <UseNewtonsoft value="true" />
</SwaggerOptions>
```

You can apply this configuration when you reach Section 8-Web.config in the @deploy-linux-rest.
